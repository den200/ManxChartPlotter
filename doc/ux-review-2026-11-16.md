# Part 1. Black Belt review: Manx chart plotter UX (digital mode)

Reviewed: 2026-11-16 · Phase reached: Analyze · Evidence reviewed: 18 captures of the release build at 1280 × 720 points with the Danish o-charts set (`MANX_SHOT` hooks), and the source of the menu bar, windows, tap handling and key handling (`src/render/ui*.rs`, `src/bin/manx.rs`, `src/render/state.rs`).

## Verdict

| Gate | Score | Decision | Knock-out issues |
|---|---|---|---|

| Measure | 25 | **FAIL** | M2 Measurement system validated = 0; M4 Baseline stability = 0 |

The gates fail because there is no UX project to score: no stated problem, no target, no measured session. That is a statement about evidence, not about the interface. The interface itself has one clear constraint: **building and editing a route**. The editor is a window that sits on the chart it asks you to tap, and every correction goes through 16-point list buttons. Fix that first.

The rubric is the skill's house standard, not a published one.

# Part 2. Bug hunt

Three readers covered the UI and input, `src/nav` with `src/geo.rs`, and Signal K, shop, tile cache and pick. All findings come from reading code. **No test was written and nothing was reproduced.** I re-read the code behind the nine marked ✔ and it matches the claim; the rest are as reported.

## Status

All 34 were fixed between 2026-11-16 and 2026-11-17, each with a test whose expected value comes from the spec, the geometry or the protocol. None turned out not to be a bug.

Confirmed by experiment, not only by reading:

- B1 on the public Signal K demo server: 1 vessel with the old subscription, 161 with the new; the app then showed live AIS traffic.
- B21 against a slow local server: the old configuration failed with `Timeout(RecvResponse)` two bytes into the body.

Fixed differently from the first suggestion:

- B6 does not compare the server's clock with ours (a Pi boots with the wrong time). It uses the smallest gap seen between the two.
- B17 unpacks to a staging folder and moves files in one by one, because an update package lands on top of an existing set.
- B33 retries a failed tile after ten seconds, so a passing fault does not leave a hole.

Not done: B21 still holds the whole package in memory while it downloads.

# Part 3. UX proposals, after reading Part 1

Part 1 counts taps. Read as a designer, its fifteen findings come down to three causes:

- **The chart is not the interface.** It can be panned and asked "what is this?". Everything else happens in a window next to it (U1, U2, U6, U7).
- **The bar is a list of modules, not of jobs.** Eight windows named after parts of the program (U10, U11, U12, U13).
- **Touch was a goal, but the widgets are desktop ones.** Floating windows, 16 pt buttons, drag-to-set number fields, hover text carrying the explanation (U3, U5, U15).

The proposals follow from those. They are designs to try, not verified fixes.

## 1. Let the chart answer "what can I do here?"

A tap opens a card docked to the bottom edge (to a side in landscape), not a floating window.

```
┌──────────────────────────────────────────────────────────┐
│ Lynetteløbet light · Fl(3) Y 10s                      ✕  │
│ 55°42.31'N 012°37.02'E · 1.2 NM · 047°T from the boat    │
│                                                          │
│ [ Go here ]  [ Add to route ]  [ Weather here ]  [ More 26 ] │
└──────────────────────────────────────────────────────────┘
```

- Lead with one object, chosen by rank: lights and buoys, then wrecks, rocks and obstructions, then named areas, then depth. Depth contours and metadata go under More.
- Plain words first. `VALDCO 6` becomes "Depth contour 6 m". The S-57 code stays under More for those who want it.
- Range and bearing from the boat cost nothing and are what a sailor asks next.
- **Go here** fills the planner's destination and asks Sail or Motor. This replaces the two pin buttons and the two text fields in the bar for the common case; typing a position stays available under Routes.
- A tap on empty water gives the same card with the depth and the same actions.
- A tap on a route leg or a waypoint gives route actions instead (see 2).

## 2. Edit routes on the chart

Replace the Routes window, while editing, with a strip docked along the bottom above the instrument bar.

```
┌──────────────────────────────────────────────────────────┐
│ Route 1 · 3 waypoints · 4.3 NM      [ Undo ] [ Follow ] [ Done ] │
└──────────────────────────────────────────────────────────┘
```

- Tap water: add a waypoint at the end.
- Drag a waypoint: move it. Draw the touch target at 44 pt whatever the symbol's size, and show the point under a magnifier offset above the finger, because the finger hides what it is placing.
- Tap a leg: insert a waypoint there. This is the dog-leg round a hazard, the most common edit.
- Tap a waypoint: a small card with Rename, Delete, "Start here".
- The list with names and leg distances remains, behind a "List" button, for the rare reorder. `Up` / `Dn` go.
- Undo covers every edit, not only delete.
- **Follow** ends editing and starts guidance. One tap, not Activate, Done, ✕.

While this strip is up, the hazards the auto-router already knows could tint a leg that crosses shallow water. That is a larger piece of work and belongs in the routing roadmap, not here.

## 3. A bar built from jobs

Today: `Charts · Instruments · Routes · Boat · Display · Weather · Log · Safety · from · to · Sail · Motor`.

Proposed, left to right:

```
[ Go to… ]  [ Routes ]  [ Weather ]  [ Anchor ]          [ ☀/☾ ]  [ ☰ ]
```

| Control | What it holds | Why |
|---|---|---|
| Go to… | The planner: destination, Sail or Motor | The question a plotter exists to answer, as one verb |
| Routes | The route list; New route | Daily |
| Weather | The sheet and layers | Daily |
| Anchor | Drop / raise, radius | Used every night at anchor; today it is inside Safety |
| ☀/☾ | Day → Dusk → Night, one tap each | Every evening; today 3 taps |
| ☰ | Charts, Connection, Boat, Display, Alarms, Log, About | Set-up and occasional |

- Six controls, not thirteen.
- "Instruments" becomes "Connection", which is what the window is for. Units and bar position move to Display.
- Alarms get one home. The collision thresholds leave Instruments.
- Weather-routing choices (forecast, hours, waves, currents) move to the Go to… panel under "Options", worded for a sailor: "Avoid waves over 2.5 m", "Use tidal currents", "Forecast: 48 hours". The polar shows as "Hallberg-Rassy 352", not a path.
- One "Sail" only: the row button in Routes becomes "Re-route for weather".

On the Pi the bar could go to the left edge as a rail of icons with labels. A 16:9 screen has width to spare and height to save. Try both in a capture before choosing.

## 4. Controls that live on the chart

Bottom-right, stacked, each 44 pt:

```
[ + ]
[ − ]
[ ◎ ]   follow the boat (filled when following)
[ N ]   compass: north-up / head-up
```

Bottom-left: **MOB**, in the same place in every state. Panels that open along the bottom push the chart up, not the button; if the weather sheet needs the corner, the sheet gives way.

Bottom-centre, above the instrument bar: a scale bar ("0.5 NM"). It answers "how far is that?" without a tap, and it is expected on a chart.

Modes speak through a chip at the top-centre of the chart, as the planner's pin already does: "Tap the chart to add a waypoint · Cancel". The permanent hint row goes, and the chart stops jumping.

## 5. When a plan finishes, say so and offer the next step

```
┌──────────────────────────────────────────────────────────┐
│ Route to Helsingør · 23 NM · 4 h 50 min · arrive 16:40      │
│ Wind 12–18 kn on the beam, 1 tack                          │
│ [ Follow ]  [ Look at it ]  [ Discard ]                     │
└──────────────────────────────────────────────────────────┘
```

While routing: a progress line in the same place with Cancel, not a spinner in the bar. A plan that fails says why in the card, not in a truncated line whose full text needs a hover that touch does not have.

## 6. Empty states that lead somewhere

| State | Now | Proposed |
|---|---|---|
| No Signal K | Four dashes, three dots | "Not connected to the boat · **Connect**" across the bar |
| Connected, no GPS | Dashes | "Waiting for GPS" on the position tiles |
| No charts | (not seen) | "No charts yet · **Get charts**" on the basemap |
| No routes | A sentence naming three ways | Two buttons: New route, Import GPX |

Stale values should look stale: greyed with their age ("12 s ago"), never a live-looking number. This is the display side of bugs B5 and B6.

## 7. Touch rules to hold everywhere

- 44 pt minimum for anything tappable, 8 pt between targets. No `small_button`.
- No value set by dragging a number. Use − / + steppers or a short list of sensible values (anchor circle: 20, 30, 40, 60, 80 m).
- Nothing explained only on hover. If the text matters it is on screen or one tap away.
- Panels dock to an edge. Floating, draggable, resizable windows are for set-up screens only.
- An interface size setting: Small, Medium, Large, applied as egui's zoom factor on top of the OS scale. Default it from the screen's physical size where the OS reports one.
- Night: check contrast of the bar text against the night background on the real panel. In the capture it is faint, which may be right for dark-adapted eyes and wrong at dusk.

## Order I would build it in

| Step | What | Why first |
|---|---|---|
| 1 | Fixed MOB, zoom buttons, scale bar, chip instead of hint row | Small, safe, visible; no flow changes |
| 2 | Plan-finished card with Follow; palette button | Two top tasks drop to one tap |
| 3 | Tap card with ranking and actions | Makes the chart the starting point |
| 4 | On-chart route editing | The constraint; the largest piece |
| 5 | Bar regrouping and one home per setting | Best done once 3 and 4 have removed the planner fields from the bar |
| 6 | Size setting and the touch rules | Needs the real screen to judge |

After step 4, run the five-user test on T3 and T6. That is the measurement Part 1 says is missing, and it tells whether step 5 is worth doing.

## What I would not do

- A first-run wizard. Good empty states do the same job and never get in the way again.
- Gestures with no visible control (long-press menus, two-finger tap to measure) as the only way to anything. They are fine as shortcuts.
- More instrument tiles or pages before the bar's empty and stale states are right.
